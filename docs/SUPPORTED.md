# Supported canonical language

The main schema-check command is v2. The retained v1 byte checker is the fixed input format for the token component. Passing v2 evidence into the v1 token component is unsupported and fails; numeric/array additions do not silently acquire token guarantees.

Both versions use necessary finite/string guards, canonical compact JSON, sorted object keys, Unicode scalar strings, and Boolean combinations only when the guarded universe can be established. Finite enum/const supports nested JSON values. Closed finite objects require explicit closure and provably finite property domains. Missing required names in a closed object can make the language empty. String patterns are a documented restricted full-string fragment: anchored literals and supported positive classes/ranges with the implemented quantifiers, rather than arbitrary regular expressions. Open objects, recursive references, general regex and unknown keywords remain unsupported. Consult the frozen v1 README in `components/schema-check/next4/` for its exact string spellings.

v2 adds exact rational bounds for number/integer, exclusive bounds, multipleOf, and Boolean combinations under a necessary numeric guard. It does not treat a numeric keyword as if it imposed a numeric type. Comparisons/divisibility use exact rational arithmetic, not floating-point rounding. Numeric feature construction may return UNKNOWN for large moduli. Canonical numeric output is finite decimal, with no exponent, redundant trailing fractional zeros or negative zero; 1, 1.0 and 1e0 refer to the same value, canonically written 1.

v2 supports schema-valued items, minItems/maxItems and uniqueItems when the item domain and resulting array domain are provably finite. A finite item domain plus uniqueItems can itself bound array length. JSON numeric equality treats 1 and 1.0 alike and keeps true distinct from 1. Unrestricted/infinite-domain arrays, prefixItems and infinite-domain uniqueItems remain outside scope. A length bound alone does not make an arbitrary item domain finite. Unknown nested keywords are checked before simplification.

Distances count bytes, not characters or model tokens. String length constraints count Unicode code points. Byte sequences must end as canonical valid UTF-8 JSON; a supplied prefix may end midway through UTF-8. Suffix text is an optional display: bytes/hex remain authoritative. An impossible canonical prefix does not rule out a different serialization of the same JSON value.

Each CLI isolates the mathematical worker with at most 30 seconds, 100,000 automaton states, a 2,000,000-entry completion budget, 1MiB schema/prefix input and 32MiB artifact I/O. The exact limits and result format are recorded in artifacts. The packet verifier additionally monitors combined RSS below 2GiB. A supported proof is conditional on the documented semantic/encoding kernels, not a full implementation of the JSON Schema standard or a formally checked theorem.
